# ReCloud 业务 × AI Agent 能力对照

## 现有业务模块与 Agent 结合点

### 1. 小说导入 & 章节切分

**现状**：启动时扫描 `novels/` 目录，正则切分章节，自动入库（支持 UTF-8/GBK 编码检测）

| Agent 能力 | 说明 | 技术点 |
|-----------|------|--------|
| 内容质量自动检测 | 导入时检测乱码率、段落完整性、编码异常 | 规则引擎 + LLM 文本分析 |
| 元数据摘要生成 | 自动生成主要角色、背景设定、章节概要 | LLM 摘要 |
| 重复导入检测 | 检测是否已有相同/相似版本的小说入库 | 文本相似度 |

---

### 2. 普通批注（type=0）

**现状**：用户选中文字 → 浮动工具栏 → 写批注弹窗 → 正文黄色高亮 → 侧边栏显示

| Agent 能力 | 说明 | 技术点 |
|-----------|------|--------|
| 自动分类标签 | 批注提交时自动打标签：赏析/疑问/解读/纠错/联想 | LLM 分类 |
| 相似批注推荐 | 提交时用 RAG 检索已有相似批注，提示"已有类似讨论" | Embedding + 向量检索 |
| 质量评估 | 标记低质量批注（纯表情、无意义内容） | 规则 + LLM 分类 |

---

### 3. 数据校验批注（type=1）

**现状**：用户切换到"数据校验"类型 → 提交问题描述 → 存库 → 正文橙色高亮

| Agent 能力 | 说明 | 技术点 |
|-----------|------|--------|
| 自动汇总 | 按问题类型聚类（乱码/广告/排版/内容错误），按章节汇总生成报告 | 文本聚类 + LLM 摘要 |
| 去重合并 | 语义相似度检测重复报告，自动关联并计数 | RAG 相似度 |
| 优先级分派 | 根据问题严重程度自动排优先级 | LLM 分类 |
| 状态流转 | 待处理 → 已确认 → 已修复，Agent 辅助确认是否已修复 | 规则引擎 + 差异检测 |

---

### 4. 讨论/评论

**现状**：批注下支持多用户评论，支持删除自己的评论

| Agent 能力 | 说明 | 技术点 |
|-----------|------|--------|
| 内容审核 | 评论提交时自动检测违规（人身攻击、广告、敏感内容） | 分层审核（规则+LLM+人工） |
| 精华标记 | 自动识别深度分析、有引用依据、多人回复的高质量讨论 | LLM 质量评估 |
| 摘要生成 | 长讨论串自动生成摘要，新用户快速了解讨论要点 | LLM 摘要 |

---

### 5. 用户系统

**现状**：用户名注册（无密码），localStorage 登录态

| Agent 能力 | 说明 | 技术点 |
|-----------|------|--------|
| 用户画像 | 自动统计批注偏好、活跃度、贡献质量 | 结构化存储 + 统计分析 |
| 异常行为检测 | 短时间大量提交、重复内容灌水、恶意刷批注 | 频率异常检测 |
| 信誉系统 | 基于批注质量和社区行为自动计算信誉分 | 规则 + 权重计算 |

---

### 6. 管理端（尚未实现，Agent 能力的汇聚点）

| Agent 能力 | 说明 | 技术点 |
|-----------|------|--------|
| 对话式管理助手 | 管理员用自然语言查询社区数据 | Function Calling + 多工具路由 |
| 自动周报 | 每周生成社区运营报告（新增批注/讨论/校验处理进度） | LLM 报告生成 |
| 审核队列管理 | Agent 预审 + 人工确认，提升审核效率 | LangGraph 状态图 + Human-in-the-loop |

## 全貌图

```
用户端（已有）                    Agent 能力层（待加）              管理端（待做）
─────────────                    ────────────────              ─────────────
小说导入        ──→  内容质量自动检测                              自动周报
普通批注        ──→  自动分类 + 相似推荐                          对话式助手
数据校验批注    ──→  聚类汇总 + 去重 + 优先级  ──→  管理员审核队列
讨论/评论       ──→  内容审核 + 精华标记                          用户管理
用户行为        ──→  异常检测 + 画像构建                          封禁决策
```

**核心逻辑**：用户端产生的数据 → Agent 层加工处理 → 管理端供管理员决策。Agent 不替代用户交流，而是帮管理者从海量数据中提取信息、发现异常、辅助决策。

## 面试表述建议

> "这个项目用户端是一个小说批注社区，后端用 Java Spring Boot，Agent 服务用 Python + LangGraph 构建。Agent 主要做三件事：
> 1. **内容审核**：批注和评论提交时，先过规则引擎（敏感词、频率异常），再交给 LLM 做语义分类，可疑内容进人工队列——分层架构确保关键违规不漏掉。
> 2. **数据校验汇总**：用户提交的数据校验批注用 RAG 做语义聚类，按问题类型和章节自动汇总生成报告，去重合并重复反馈。
> 3. **管理端助手**：管理员通过自然语言查询社区数据，Agent 理解意图后调用对应工具（SQL查询、向量检索、报告生成），返回结构化回答。
>
> Java 和 Python 通过 REST API 通信，异步任务走 Redis 队列。RAG 部分用 BGE-M3 做 embedding，Milvus 做向量检索，BM25 + 向量混合检索再 Rerank。评估用 RAGAS 框架 + 人工标注测试集。"
